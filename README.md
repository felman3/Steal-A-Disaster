# Steal a Disaster

A Roblox game about stealing **Disaster Cores** from increasingly dangerous zones,
running them home, incubating them into miniature **disasters** that earn money,
and upgrading your speed and base so you can push further down the route.

Inspired by the zone-progression and stealing structure of *Steal an Egg*. All
content, names, models, code and UI are original, built entirely from parts
(no external assets).

## Play it in Studio

**Option A — no tools needed**
```bash
npm install
```
```bash
npm run build
```
Open `build/StealADisaster.rbxlx` in Roblox Studio and press **Play**. The world
is generated by the server at runtime, so the place looks empty in edit mode.

**Option B — Rojo**: `rojo serve` (uses `default.project.json`) and connect with the
Rojo plugin.

Enable *Game Settings → Security → Studio Access to API Services* if you want
saving in Studio. Without it the game still runs, but the session isn't saved
(this is detected automatically).

### Studio test commands (only active in Studio)
`/money 100000`, `/speed 20000`, `/core BlackHoleCore`, `/hatch`, `/frenzy`,
`/guardians off`, `/reset`.

## The loop
1. **Train** on your base treadmill. The server counts steps at a capped rate, and each
   step adds Speed. Speed raises your WalkSpeed.
2. **Run** down the central route. Every zone is open to explore, but **stealing**
   needs the zone's Speed, which is shown on the gate and on every core.
3. **Steal** a core from the nest while dodging the zone's **guardian** (it sleeps,
   patrols and chases anyone carrying a core).
4. **Escape home.** Carrying slows you down according to the core's rarity weight. A beam and a HUD
   objective point home. Dying, getting tagged, disconnecting or teleporting
   returns the core to where it came from.
5. **Incubate.** Delivered cores go into pods. A neon fill and a billboard show progress.
6. **Collect.** Disasters hatch onto display pedestals and earn money every second.
   Mutations (Charged ×1.5 … Corrupted ×5) can roll at spawn or at hatch.
7. **Upgrade** the treadmill, backpack, pods, pedestals and shield. Your base
   visibly unlocks slots and gains decor tiers.
8. **Every 5 minutes:** a 30 s warning, then the world's cores refresh and a
   **10 s Chaos Frenzy** starts, with rarer odds, Chaos Cores, ×4 incubation and boosted
   mutations. Owned items and money are never touched.
9. **PvP:** steal incubating cores from other bases (hold E). Owners can tag the
   thief to get it back, or lock their base with the shield.

Zones: Suburb → Overgrowth → Droughtlands → Frostfall → Magma Basin → Deep Abyss
→ Prehistoric → Skylands → Void Realm. See [docs/DESIGN.md](docs/DESIGN.md) for the
research, map layout and progression curve.

## Architecture
```
src/shared/            ReplicatedStorage.Shared
  Config/GameConfig    all content + balance (pure data)
  Logic/*              pure, unit-tested rules (speed, carry, economy, incubation,
                       spawning, upgrades, events, rate limiter, data schema, layout)
  Models/*             Kit (part helpers), CoreModels, DisasterModels, GuardianModels
  Remotes, Signal, Util
src/server/            ServerScriptService.Server
  Main.server          builds the world, Init/Start services in order
  Services/            PlayerData, Zone, Base, Economy, Speed, Event, CoreSpawn,
                       Carry, Steal, Incubator, DisasterCollection, Guardian,
                       Upgrade, Dev (Studio only)
  World/               MapBuilder (hub, gates, nests), BaseBuilder, Zones/<ZoneId>
src/client/            StarterPlayerScripts.Client
  Main.client, State, UI/{Theme,Hud,Panels,Announcer}, World/WorldFx
```
The server is authoritative for everything. Clients send only two intents
(`RequestUpgrade`, `RequestShield`). Pickups use server-side ProximityPrompts with
server-measured range, delivery is detected from server positions, and ownership
transfers only on delivery. Remotes are rate-limited and saved data is
sanitized on load.

## Tests
```bash
npm test
```
```bash
npm run lint
```
There's no Roblox Studio in the build environment, so the project ships a
headless harness (`tests/harness`). It's a Roblox API mock (typed instance property
schemas, CFrame/Vector3 math, virtual-time scheduler, Players/DataStore/RunService/
TweenService/CollectionService) that runs the **real** server and client code in a
Lua 5.4 VM. That's why all source sticks to the Luau ∩ Lua 5.4 subset
(see [docs/ART_CONTRACT.md](docs/ART_CONTRACT.md)).

- `logic.spec`: unit tests for every rule module
- `loop.spec`: the full vertical slice (train → steal → carry → deliver → incubate →
  hatch → income → upgrade), plus speed gates, range checks, teleport, death and
  disconnect, guardian tags, capacity, PvP theft, owner tags, victims leaving mid-steal,
  shields, persistence and retries, tampered data, the event cycle, remote spam, and dev commands
- `client.spec`: server and client in one VM with bridged remotes; HUD, shop round-trip,
  index, zone banners, run-home objective, animator, prompt filtering
- `models.spec`: every core, disaster and guardian model against the art contract
- `zones.spec`: every zone builder against the zone contract (walkable corridor,
  clear nest, ground coverage, bounds, part budget)
- `balance.spec`: a simulated player checks the progression pace

`node tools/preview.js` renders an approximate **mock** preview of the world
(three.js, headless). It's only useful for layout and silhouettes; it doesn't
replace a look in Studio.
